# 새 PC 이관 — NixOS 설치 이후

ISO 설치와 첫 SSD 부팅을 마친 뒤 메인 작업 환경을 옮기는 절차다. Cyborg에서 확인한 흐름을 바탕으로 하며, 주소·장치·버전은 기기마다 확인한다.

1. **대상 확인과 데이터 복원.** SSH 호스트 키를 신뢰할 수 있는 경로로 대조하고, 접속한 기기명·마운트·여유 공간을 확인한다. 홈 기준 상대 경로를 유지하되 실경로와 심볼릭 링크를 구분한다. 원본 데이터와 다시 만들 수 있는 빌드·캐시를 나눠 후자는 제외한다. 임시 경로로 복사한 뒤 체크섬을 비교하고, 기존 부분본은 보존한 채 배치한다. Cyborg에서는 USB 복원 중 연결 끊김/I/O 오류가 두 번 났다. 언마운트 상태에서 ext4 읽기 전용 검사(`e2fsck -fn`)는 통과했지만 연결 안정성을 증명하지는 않아 해당 아카이브는 LAN으로 다시 전송했다. 저장소 트리와 Org를 포함한 동기화 트리는 각각 체크섬을 대조했다. Syncthing 기기 등록은 운영자가 직접 한다.
2. **선언 설정과 도구.** `~/nixos-config`가 실제 리포 `~/repos/gh/nixos-config`를 가리키도록 준비한다. Cyborg에서는 링크와 Home Manager의 tmux 설정을 확인했다. `scripts/external-packages.sh`의 pnpm/harness 단계로 Pi·Claude·Codex를 설치하고 `gog` 설치와 인증은 분리한다. `agent-config`의 전체 점검으로 빠진 의존성을 찾되, 시간 의존 테스트 실패를 무시하고 전체 통과로 기록하지 않는다. Entwurf는 npm 소비자 배포판을 설치하고 소스 체크아웃과 런타임 등록을 구분한다. 브리지 스모크 테스트 뒤 Codex 최초 훅 신뢰 승인과 서비스 로그인은 운영자가 직접 한다. `switch`는 별도로 결정한다.
3. **사용자 폰트.** Nix/Home Manager로 선언한 폰트는 설정으로 복원하고, 직접 설치한 폰트는 라이선스상 복사를 허용하는 파일만 골라 새 기기의 `~/.local/share/fonts/` 아래 같은 상대 경로로 `rsync -a --checksum` 한다. 새 기기에서 `fc-cache -f ~/.local/share/fonts`를 실행하고 `fc-match '<정확한 패밀리 이름>'`이 대체 폰트가 아닌 옮긴 파일을 가리키는지 확인한다. Cyborg에서는 사용자 TTF 16개를 옮긴 뒤 해당 Regular TTF가 선택되는 것을 확인했다. 필요하면 터미널이나 Emacs에서 폰트 패밀리를 다시 선택하고 앱을 재시작한다.
4. **비밀과 복호화 검증.** 범용 복사·동기화에 섞지 않는다. 임시 키 파일은 `umask 077`로 만들고 권한 0600, 대상 및 덮어쓰기 여부를 확인한다. `pass` 저장소를 복사한 뒤 `ln -sT ~/repos/gh/password-store ~/.password-store`로 연결한다(이미 경로가 있으면 중단). 기존 기기의 대화형 터미널에서 GPG 비밀 키를 임시 파일로 export하고, 검증한 SSH로 전송한다. 새 기기 TTY에서 파일 경로로 import해 입력 스트림과 암호 프롬프트를 분리한다. Cyborg에서 stdin 파이프 import는 `Inappropriate ioctl for device`로 실패했고 TTY 방식은 성공했다. 새 기기의 GPG 홈 권한 0700과 키·서브키를 확인하고, `pass` 복호화는 평문 출력 없이 시험한다. 검증 뒤 양쪽 임시 파일을 삭제한다. 외부 서비스 로그인은 자동 복원되지 않는다.
5. **세션과 기억.** 새 기기에서는 새 세션만 연다. 옛 기록은 원 기기 레이블을 유지한 임베딩 전용 코퍼스로 보존한다. Cyborg 사례에서 세션 전송 체크섬 통과와 기존 매니페스트의 누락 포인터는 별개였다. annex를 무조건 재초기화하거나 원본 매니페스트를 덮어쓰지 않는다. 기존 객체·이력을 재연결해 검증하고 API 호출 없는 점검(API-0)을 마친 뒤에만 작업 정본을 전환한다. 유료 임베딩과 게시도 별도 결정이다.
